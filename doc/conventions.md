# Правила написания кода

> Техническое видение и архитектура: @doc/vision.md

## Стиль кода

- **Функции только** - БЕЗ классов и ООП
- **snake_case** для функций и переменных
- **Максимум 20 строк на функцию** - разбивать сложные функции
- **Явные типы** - указывать типы аргументов и возвращаемых значений
- **Docstring только для публичных функций** - краткое описание

## Асинхронность

- **async/await для всех I/O операций** (Telegram API, LLM API)
- **НЕ блокировать event loop** - использовать асинхронные библиотеки
- **Одна async функция = одна задача** - не усложнять

## Обработка ошибок

- **Fail Fast** - проверять входные данные сразу
- **Логировать ошибки** - `logger.error()` с контекстом
- **НЕ глушить исключения** - пропускать критические ошибки выше
- **Graceful degradation** - бот должен отвечать пользователю даже при ошибках LLM

## Работа с данными

- **Простые dict/list** - БЕЗ сложных структур данных
- **Валидация входных данных** - проверять chat_id, message content
- **Ограничения** - max_history_messages из конфига
- **БЕЗ мутации глобальных переменных** - передавать через параметры

## Зависимости

- **Минимум импортов** - только необходимые библиотеки
- **БЕЗ * импортов** - явно указывать что импортируем
- **Группировка импортов**: stdlib, сторонние, локальные модули

## Логирование в коде

- **logger.info()** для важных событий (старт, новое сообщение)
- **logger.error()** для ошибок с stack trace
- **БЕЗ секретов в логах** - не выводить токены и ключи
- **Контекст в сообщениях** - указывать chat_id, длину сообщения

## Тестирование

- **Один тест = один сценарий** - простые функциональные тесты
- **БЕЗ сложных mock'ов** - тестировать реальное поведение
- **Основные флоу**: /start, обычное сообщение, ошибка LLM
- **pytest fixtures** для общих данных (конфиг, тестовые сообщения)

## Безопасность

- **НЕ логировать пользовательские сообщения полностью** - только metadata
- **Санитизация входных данных** - проверка длины сообщений
- **Rate limiting** не требуется для MVP, но учитывать возможность

---

**Главное:** Читаемый, простой код без магии. Каждая функция делает одну вещь.
