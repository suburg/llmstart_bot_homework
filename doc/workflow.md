# Workflow разработки

> План разработки: @doc/tasklist.md | Техническое видение: @doc/vision.md | Правила кода: @doc/conventions.md

## 🔄 Процесс работы с итерациями

### 1. Подготовка итерации
- [ ] Изучить задачи текущей итерации из @doc/tasklist.md
- [ ] Проанализировать требования из @doc/vision.md для данной итерации
- [ ] **ОБЯЗАТЕЛЬНО:** Предложить техническое решение с примерами кода
- [ ] Дождаться согласования решения перед реализацией

### 2. Реализация
- [ ] Создать/изменить файлы согласно @doc/conventions.md
- [ ] Следовать структуре проекта из @doc/vision.md раздел 3
- [ ] Реализовать только задачи текущей итерации
- [ ] **НЕ переходить к следующей итерации без подтверждения**

### 3. Завершение итерации
- [ ] Провести тест согласно критерию в @doc/tasklist.md
- [ ] Отметить выполненные задачи в @doc/tasklist.md (поставить [x])
- [ ] Обновить "Отчет по прогрессу" в @doc/tasklist.md
- [ ] Зафиксировать изменения: `git add . && git commit -m "Iteration X: feature description"`
- [ ] Дождаться подтверждения перехода к следующей итерации

## ⚠️ Важные правила

### Согласование решений
- **Всегда показывать код** перед реализацией
- Объяснять архитектурные решения
- Указывать какие файлы будут созданы/изменены
- Ждать одобрения для продолжения

### Обновление прогресса
```markdown
# В @doc/tasklist.md обновить:
- [x] Выполненная задача
- [ ] Невыполненная задача

# Изменить статус:
**Завершенные итерации:** 1/6
- [x] **Итерация 1:** Базовая инфраструктура - Завершено
```

### Коммиты
- Один коммит = одна итерация
- Сообщения коммитов на **английском языке**
- Описательные сообщения: `git commit -m "Iteration X: feature description"`
- Коммит только после успешного тестирования

## 🚫 Что НЕ делать

- НЕ пропускать этап согласования
- НЕ реализовывать задачи из будущих итераций
- НЕ изменять архитектуру без обсуждения
- НЕ забывать обновлять @doc/tasklist.md
- НЕ делать коммит без тестирования

## ✅ Критерии качества

- Код соответствует @doc/conventions.md
- Тест итерации пройден успешно  
- Все задачи итерации отмечены как выполненные
- Прогресс обновлен в @doc/tasklist.md
- Изменения зафиксированы в git

---

**Помни:** Медленно и качественно лучше, чем быстро и с ошибками.
