# Техническое видение проекта: ИИ-ассистент Telegram бот

## 1. Технологии

**Основной стек:**
- **Python 3.11+** - основной язык разработки
- **aiogram** - библиотека для Telegram Bot API (асинхронная, современная)
- **OpenRouter + OpenAI client** - доступ к различным LLM через единый интерфейс
- **python-dotenv** - управление переменными окружения

**Инструменты разработки:**
- **uv** - управление зависимостями (быстрый, современный)
- **pytest** - фреймворк для тестирования
- **Make** - автоматизация сборки и запуска

**Деплой и контейнеризация:**
- **Docker** - контейнеризация (опционально для деплоя)

**Принципы:**
- Никаких дополнительных фреймворков - простой асинхронный скрипт
- Никаких БД - состояние диалогов в памяти (словари Python)
- Максимальная простота и минимализм

## 2. Принципы разработки

- **KISS (Keep It Simple, Stupid)** - максимальная простота решений
- **MVP подход** - минимально жизнеспособный продукт для проверки гипотезы
- **Итеративная разработка** - быстрые циклы: разработка → тестирование → улучшение
- **Модульность** - разделение функциональности на независимые модули
- **Функциональный подход** - без ООП, используем функции и модули
- **"Работающий код важнее чистого кода"** - сначала делаем работающее решение
- **Функциональное тестирование** - тестируем основные пользовательские сценарии
- **Fail Fast** - быстро выявляем проблемы и исправляем

## 4. Архитектура проекта

**Компоненты:**
1. **Telegram Bot Handler** - принимает сообщения, отправляет ответы, содержит логику обработки сообщений
2. **LLM Client** - взаимодействие с OpenRouter/OpenAI API
3. **Memory Storage** - хранение истории диалогов в памяти

**Поток данных:**
```
User Message → Telegram → Bot Handler → Memory Storage (get context) → 
→ LLM Client → OpenRouter → LLM Response → Bot Handler → 
→ Memory Storage (save context) → Telegram → User
```

**Принципы архитектуры:**
- Линейный поток обработки сообщений
- Stateless компоненты (кроме Memory Storage)
- Минимум абстракций
- Прямые вызовы функций без сложных паттернов

## 9. Деплой

**Варианты деплоя через Make:**

```makefile
# Локальная разработка/тестирование
make install        # uv sync - установка зависимостей
make run           # uv run src/main.py - запуск бота
make test          # pytest - запуск тестов

# Docker деплой (на своей машине/VPS)
make docker-build   # docker build -t telegram-bot .
make docker-deploy  # docker run -d --env-file .env telegram-bot
make docker-stop    # остановка и удаление контейнера
make docker-logs    # просмотр логов контейнера

# VPS без Docker
make install-prod   # установка зависимостей на сервере
make run-prod      # запуск в фоне (nohup/systemd)
```

**Процесс деплоя:**
1. Настройка переменных окружения (`.env`)
2. Создание системного промпта (`prompts/system.txt`)
3. Выбор способа деплоя:
   - Локально: `make install && make run`
   - Docker: `make docker-build && make docker-deploy`

**Требования к серверу:**
- Python 3.11+ (для локального) или Docker
- 256MB RAM (минимум)
- Постоянное интернет-соединение

**Принципы:**
- Максимальная простота через Make команды
- Один процесс, никаких сложных оркестраций
- Автоматизация всего пайплайна

## 11. Логгирование

**Настройка логгера:**

```python
import logging

logging.basicConfig(
    level=config["log_level"],
    format='%(asctime)s - %(name)s - %(levelname)s - %(message)s',
    handlers=[
        logging.FileHandler('bot.log'),
        logging.StreamHandler()  # консоль для разработки
    ]
)

logger = logging.getLogger(__name__)
```

**Что логируем:**
- Запуск/остановка бота
- Входящие сообщения от пользователей  
- Запросы и ответы LLM (без секретных данных)
- Ошибки и исключения

**Уровни логирования:**
- `INFO` - основные события (запуск, сообщения)
- `ERROR` - ошибки API, исключения
- `DEBUG` - детальная отладочная информация

**Принципы:**
- Один лог-файл `bot.log`
- Ротация логов НЕ требуется для MVP
- Никаких секретных данных в логах
- Простое текстовое форматирование
